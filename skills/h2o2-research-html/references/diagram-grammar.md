# Diagram grammar

从 OpenClaw 示例归纳：图只回答“任务如何使用 MCP，工具上下文从哪里回到 Agent”；选型对比和 POC 不再成为第二张图。

## 选择和聚合

- 先写下图要回答的一个问题；图不能帮助回答时，改为短文、两三块分组或表。
- 真实时间／控制／数据方向才用箭头；包含和归属用容器、位置与留白。对比用并排或矩阵。
- 主要节点约 5–7 个是启发式。超过 7 个或混入 3 种以上关系时，先按问题聚合，再决定是否拆图；完整事实留在可展开证据中，不丢弃。
- 一个主阅读方向。桌面横排可以在手机重新纵排；请求与返回可为一组反向通道，但不能误画成新的时间顺序。

## 每条线的检查

- 用一句动词解释，例如“调用”“提供”“生成”“依赖”。不能解释或没有来源，就不画。
- 起点落在发出者边缘，箭头落在接收者边缘；不交叉、不绕回、不指向空白。容器内的子对象不靠箭头表示归属。
- 不因排版对称创造关系。OpenClaw 示例的 MCP → Agent 返回箭头不能变成 MCP → 行为后果的直线，也不能把工具描述和 Agent 生成的调用参数都归为攻击者直接控制。
- 明确拟议状态；没有日志、时间和结果时不能画成真实执行 Trace。研究页也不能凭调用日志补出完整工具环境。

## 视觉语义

- 色彩表示对象类别，状态另用标记、边框或文字。红色受控区域只表示注入位置，不表示攻击已成功。
- 文本不能盖线，连线标签与节点文字分开。手机保留同一语义并重新布局，避免整个 SVG 缩小导致字号下降。
- 给 SVG 提供 `title` / `desc` 或等价的文字说明。图的关系和证据在离线文件内可读，不只存在于外部链接。
