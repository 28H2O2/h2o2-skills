# H2O2 Research HTML

先做页面，再从真实阅读体验决定结构。此 Skill 不需要 Scenario / Case / Run / Events 数据，也不要求 Thinking、Scene、时间线、选择器或 Inspector。

## 从两个例子开始

- `assets/openclaw-brief.html`：先露出“OpenClaw 安全评测 / 先试 Canary / 未实测”，只有一张 MCP 关系图。选型对比、POC、历史案例、问题与来源都可展开。图是拟议关系，不是实际 Trace。
- `assets/source-review.html`：一个源码控制流判断，默认没有图；5 行源码和建议测试折叠起来。不要给没有复杂关系的结论补一张架构图。

示例是阅读方式参考，内容不能直接当作用户项目的事实；也不要照搬其章节、数量或配色来凑结构。

## 制作过程

1. 读源材料，确定读者最先需要回答的一个问题，写一句有证据支撑的直白结论。证据不足时把结论写成待验证判断，保留必要状态。
2. **先完成示例或真实报告的首屏。** 视觉权重为研究对象／结论、必要的主视觉、至多两条支撑事实。标题用研究对象名称；删掉“通过可视化深入理解”等导语。
3. 默认至多一张主视觉，按关系选表达：真实执行主链用流程；归属用容器与留白；差异用并排结构或表；源码结论用展开证据。关系不清楚或文字已经说明问题时不画图。需要连线时读 `references/diagram-grammar.md`。
4. 把次要对比、源码全文、历史案例、计划、待确认项和来源放在次级阅读区或原生 `details` 中。折叠保留原始数据，不丢事实；关键状态和会改变主结论的限制仍应直接可见。用标题和留白分组，不给每段文字套卡片。
5. 逐句检查可见文字：没有新增事实、操作、证据或必要限制的就删。图已经说明关系时，不再放重复的时间线或完整复述。不要通过缩小字号把所有内容塞进一屏。
6. 在 1440×900 截图里判断第一眼落在哪，能否迅速定位研究对象、主结论和关系。再检查 390px，必要时补 320px；窄屏可以延长页面或重新排图，不缩成不可读的缩略图。确认展开、来源跳转、键盘焦点和页面宽度；实际看截图后再交付。

## 事实和实现

- 区分已验证事实、静态源码判断、建议、拟议 POC、运行结果。每条关系有来源；拟议图明确写“计划／拟议”，不能画成真实 Trace。
- 原始日志未提供时，引用已有汇总并注明待核对，不冒充自行复核。链接到支持具体事实的文档或源码；已知版本时固定版本／commit，不知道时直说。
- 不把不同 Agent、模型或历史实验的结果混算成当前研究对象的成功率。敏感原文按任务上下文脱敏。
- 单文件、内嵌 CSS / 必要的原生 JS / SVG，离线打开不请求 API、CDN 或外部字体。源文本用安全 DOM API；嵌入 JSON 时转义 HTML 上下文。
- 16px 左右正文、暖纸底、少量细线、清晰焦点即可。可选低调 `crafted by h2o2` 落款；它不是研究结果的作者声明。具体视觉 token 见 `references/visual-tokens.md`。

这不是固定报告 Schema 或自动化审计器。报告内容与形态服从用户材料，测试和来源不足之处要在交付里说清楚。
