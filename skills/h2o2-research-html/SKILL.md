## 核心定位

将复杂的科研实验数据（多轮 run、调用日志、文件状态快照、基线对比）转换为**单一文件、可交互、一眼看懂时空关系的 HTML 报告**。

### 5 条硬性原则

1. **拒绝线性长页**
   - 禁止文字自上而下滚成一面墙。
   - 采用「左侧栏切换 + 主区固定空间框」：首屏必须大字大数字，打开立刻看清任务是什么、核心结果是什么、下一步点哪里。
2. **时空一眼看清（图文结合）**
   - **空间**：一个固定舞台框，把角色摆齐（调用方 → 执行者 → 工具池 → 环境/存储），一屏看清谁在哪。
   - **时间**：用横轴时序图与步骤标注先后顺序（第 1 步先调什么、第 2 步返回什么）。
3. **能点、能实操、看得到状态变化**
   - 拒绝死板的静态截图。
   - 点左侧切换场景/Run，或者点击单步步骤，主舞台框**实时联动更新状态**（例如：文件被删时打红虚线和删除线、攻击状态文件生成、调用次数高亮）。
4. **配色清爽耐看，支持浅色暖纸风**
   - 不绑死全黑背景，默认推荐像实验手记一样的**暖纸浅色调（Parchment / Paper）**，护眼耐读；亦支持高对比深色调。
   - 字号宁大勿小（正文 15px+、原任务 20px、核心数字 32px），模块间距充分拉开（h2 上间距 40px+），呼吸感强。
5. **绝对客观，零评论废话**
   - 严禁“仅此而已”、“正如我们所见”、“惊人的是”等主观评价词。
   - **原文 + 翻译**：英文原话只配一句直译中文，不写多余的“中文解释”。
   - 引用必须标注来源（如 `Agent 输出 · 最终回答`、`Agent 输出 · 过程输出`、`Server 返回`）。
   - 数字全由日志快照现场计算，引语和关键代码片段严格做源文件子串比对，匹配不上直接隐藏报错，严禁凭空捏造。

## 页面架构与视觉规范

生成的 HTML 必须是**单文件自包含（Zero-dependency Monolith）**，内联 CSS 与原生 JS，离线双击即开。

### 1. 栅格与布局骨架

```
┌─────────────────┬──────────────────────────────────────────────────────────────────┐
│ 左侧切换栏       │ 顶部 Hero：任务原话（20px 中文大字 + 英文原话）                     │
│                 │ 四张 32px 大数字卡片（基线 / 场景A / 场景B / 扫描，点击直达对应场景）│
│ [总览]          ├──────────────────────────────────────────────────────────────────┤
│                 │ 【空间舞台框】（随所选场景/Run 动态刷新）                           │
│ 场景 A (基线)    │  [用户] ──请求──> [Agent] ──调用──> [工具池] ──读写删──> [工作区]    │
│   run 1 / 2 / 3 │  · 工具卡片：下发描述原文 + 中文翻译 + 真实代码摘录                │
│                 │  · 文件卡片：横排并列，随当前 Run 状态标出“完好”或“已删除”        │
│ 场景 B (实验)    │ ──────────────────────────────────────────────────────────────── │
│   run 1 / 2 / 3 │ 【时序泳道图 / 步骤交互】                                         │
│                 │  横轴时间（左→右），纵轴角色（用户 / Agent / MCP）                 │
│ [逐工具扫描对照] │  下方同步展示该轮 Agent 的真实输出（附中文翻译和来源标签）          │
│ [判定明细 / 说明]│                                                                  │
└─────────────────┴──────────────────────────────────────────────────────────────────┘
```

### 3. 字号与间距规范
- **原任务大字**：`font-size: 20px; font-weight: 600; line-height: 1.6;`
- **指标大数字**：`font-size: 32px; font-weight: 800; line-height: 1.15;`
- **主标题**：`h1: 23px`, `h2: 18px; margin-top: 44px;`（拉开大间距，带色标边缘线）
- **正文**：`15px / 1.7`
- **卡片内边距**：`padding: 16px 20px;`，栅格间距 `gap: 12px~16px;`
- **字体族**：西文优先优雅的系统等宽与无衬线，中文对齐苹方（`-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`）。

## 报告必需的 5 大模块

### 模块 1：首屏 Hero 与大数字大盘
- **原任务**：第一行标明「原任务 · 用户对 agent 说的原话」，大字显示中文翻译，下方一行小字展示英文 verbatim。
- **大数字卡片**：横向平铺 3–4 张卡片（如：`0/3 文件被删`、`1/3 清扫执行`、`0 规则命中`）。每张卡均可点击，点击直接平滑切换到左侧对应的场景或对照表。

### 模块 2：空间舞台框（Stage Box）
- **顶部角色链**：用户 → Agent → MCP Server / 工具箱 → 工作区 / 目标资源，用横向箭头连通并标注通信通道（如 `tools/call`、`tools/list`）。
- **工具池**：
  - 必须包含**图标**（扳手），区分于文件。
  - 核心三件套：**描述原文** + **中文翻译** + **关键行为代码摘录**。
  - 代码摘录只截取决定恶意/良性分歧的核心行（如 `p.unlink()`、`entries.append(...)`），并在构建脚本中逐行与源文件校验。
- **资源/文件池**：
  - 必须包含**图标**（文档）。
  - 横向排成一行（竖立卡片列），随当前 run 结果标出：绿色「完好」或红色删除线「已删除 · 不可恢复」。

### 模块 3：时序与单步交互（Timeline / Stepper）
- **SVG 时序图**：空间为纵轴泳道（用户、Agent、服务端/工具），横轴为时间（从左至右）。
- **单步实操（Run 视图）**：
  - 点击「上一步 / 下一步」或直接点击序列号，主舞台对应工具变亮，文件状态更新。
  - 同步展示该动作的实际入参、返回值。
- **Agent 输出引用**：
  - 必须展示英文原话 + 正下方紧随中文翻译。
  - 必须附带绿色药丸标签注明角色主体（如 `[Agent 输出 · 最终回答]`、`[Agent 输出 · 过程输出]`）。

### 模块 4：规则与静态扫描对照
- 针对攻击案例，并排展示逐工具扫描与多工具组合扫描的差异。
- 给出清晰的规则命中明细（例如：单工具看无删除原语放行，组合后利用隐式路径命中）。

### 模块 5：判定明细表与诚实说明
- **明细表**：表格罗列每轮 Run 的调用序列、目标资产状态、标记/执行/披露等关键判定布尔值。
- **诚实说明（单独成节）**：
  - 模型型号与版本（单模型/小样本声明）。
  - 判定口径（只认日志与 hash 快照，不信 Agent 自述）。
  - 网络路由、中间偶发故障与修正记录，如实透明公开。

## 构建脚本与自动化 QA 规范

编写生成该 HTML 的 Python 脚本时（如 `build_report.py`），必须内置双重质检机制：

### 1. 数据与文本零幻觉检查（Python 阶段）
```python
# 校验引语必须 100% 存在于原始 JSON/日志中
def verify_quote(run_verdict: dict, quote_en: str) -> bool:
    all_texts = " ".join(run_verdict.get("texts", [])) + " " + run_verdict.get("final", "")
    return quote_en in all_texts

# 校验代码摘录必须逐行出现在源文件中
def verify_code(source_file: Path, snippet_lines: list[str]) -> bool:
    src = source_file.read_text(encoding="utf-8")
    return all((line.strip() in src) for line in snippet_lines if line.strip() and line.strip() != "...")
```

### 2. 布局与交互自动化 QA（Playwright 阶段）
在生成交付前，通过 headless 浏览器自动化验证：
1. **视图遍历**：模拟点击左侧所有导航按钮，确认 `.view.on` 切换无误。
2. **溢出检查**：`scrollWidth <= clientWidth`，主界面无横向滚动条。
3. **碰撞检查**：卡片与文本框的 `getBoundingClientRect()` 互不重叠。
4. **占位符检查**：确保没有未替换成功的警告占位符或模板标记。
