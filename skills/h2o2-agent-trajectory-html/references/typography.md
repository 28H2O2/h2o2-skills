# 中文任务与场景的字体层次

先让读者看懂任务和场景，再检查字形、行长和细节。字号是起点，不能为了让所有信息塞进首屏而不断缩小。

## 字体角色与建议字号

| 内容 | 电脑端起点 | 使用方式 |
| --- | --- | --- |
| 任务／具体后果标题 | 28–40px | 名称和事实吸引注意，不写泛泛口号 |
| 中文 Instruction | 22–26px | 主阅读内容，完整译文在前 |
| 中文正文、证据解释 | 16–18px | 适当行长与段距 |
| 场景分组与关键用途名 | 14–18px | 清楚显示工具、技能、文件，不能变成 11px 小标签 |
| 事件标题／简短结果 | 14–16px | 标题说动作和对象，下一行说具体结果 |
| 技术标识与辅助路径 | 12–14px | 必要时等宽，不代替中文用途名 |
| 档案编号、次要元信息 | 11–12px | 只用于不影响理解的内容 |

中文用 PingFang SC / Microsoft YaHei / 系统无衬线，数字可用 `tabular-nums`；命令和路径用等宽。英文原文的可读性仍需保留，不因折叠而删减。字体不打包，不依赖远程字体。可选落款使用系统衬线斜体或已有签名。

手机中文任务可从 20–22px 起步，正文约 16px；通过纵排和局部代码滚动保留阅读尺度，不把桌面整图缩小。

## 排版检查

- 中文与技术标识自然分隔，但原始证据字符不改；长名称允许换行，完整路径可展开。
- 标题、用途名、原始标识分层；工具、技能、文件组的标题和首项对齐。不能靠极小字塞满 Scene。
- 数字和说明同看：输入工资、返回奖金、最终总额各有名称与单位，不能让流程标签与数字含义冲突。
- 中文全文优先，英文展开或切换；长 Thinking 不强制等宽并列双语，不把片段摘要称为全文。
- 检查对比度、文字覆盖连线、硬折行、截断与局部滚动。重要对象或关系被裁掉，即使页面宽度正常也需调整。
- 先看 1440×900 的任务与 Scene，再看选中工具／长 Thinking；最后检查 390px。只有真正查看截图和交互后，才能确认排版。
